2. DATABASE SCHEMA (SQLite via better-sqlite3 or sqlite3)
----------------------------------------------------------------------
Initialize the following tables automatically on startup in `/server/database.js`:

1. `users`:
   - id INTEGER PRIMARY KEY AUTOINCREMENT
   - username TEXT UNIQUE NOT NULL
   - email TEXT UNIQUE NOT NULL
   - password_hash TEXT NOT NULL
   - balance INTEGER DEFAULT 0
   - role TEXT DEFAULT 'user' ('user' | 'admin')
   - created_at DATETIME DEFAULT CURRENT_TIMESTAMP

2. `categories`:
   - id INTEGER PRIMARY KEY AUTOINCREMENT
   - name TEXT NOT NULL
   - slug TEXT UNIQUE NOT NULL
   - icon TEXT DEFAULT 'Package'

3. `products`:
   - id INTEGER PRIMARY KEY AUTOINCREMENT
   - category_id INTEGER
   - name TEXT NOT NULL
   - description TEXT
   - price INTEGER NOT NULL
   - type TEXT NOT NULL ('account_credentials', 'voucher_code', 'game_topup')
   - FOREIGN KEY (category_id) REFERENCES categories(id)

4. `items_stock`:
   - id INTEGER PRIMARY KEY AUTOINCREMENT
   - product_id INTEGER NOT NULL
   - content TEXT NOT NULL (e.g., "user:pass" or "VOUCHER-12345")
   - is_sold BOOLEAN DEFAULT 0
   - FOREIGN KEY (product_id) REFERENCES products(id)

5. `deposits`:
   - id INTEGER PRIMARY KEY AUTOINCREMENT
   - user_id INTEGER NOT NULL
   - amount INTEGER NOT NULL
   - payment_method TEXT NOT NULL ('DANA', 'OVO', 'GoPay', 'QRIS')
   - payment_code TEXT NOT NULL
   - status TEXT DEFAULT 'pending' ('pending', 'success', 'cancelled')
   - created_at DATETIME DEFAULT CURRENT_TIMESTAMP
   - FOREIGN KEY (user_id) REFERENCES users(id)

6. `transactions`:
   - id INTEGER PRIMARY KEY AUTOINCREMENT
   - user_id INTEGER NOT NULL
   - product_id INTEGER NOT NULL
   - price INTEGER NOT NULL
   - target_data TEXT (e.g., "User ID 12345678" for game topup, or null)
   - delivered_content TEXT
   - status TEXT DEFAULT 'completed' ('completed', 'failed')
   - created_at DATETIME DEFAULT CURRENT_TIMESTAMP
   - FOREIGN KEY (user_id) REFERENCES users(id),
   - FOREIGN KEY (product_id) REFERENCES products(id)

3. BACKEND API ENDPOINTS & LOGIC (/server)
----------------------------------------------------------------------
Implement Express routes with proper error handling and status codes:

A. Auth (`/api/auth`)
- POST `/register`: Hash password (bcryptjs), create user, return JWT token + user obj.
- POST `/login`: Verify credentials, return JWT token + user obj.
- GET `/me`: Verify JWT, return current user profile + live balance.

B. Catalog (`/api/products`)
- GET `/`: Fetch all products with category details and calculated live stock count (`COUNT(items_stock WHERE is_sold = 0)`).
- GET `/:id`: Fetch single product detail + stock status.

C. E-Wallet System (`/api/wallet`)
- POST `/deposit`: Create deposit record, generate simulated payment code/QR URL, set status='pending'.
- POST `/deposit/confirm`: [CRITICAL] Wrap in SQLite Transaction:
  1. Verify deposit status is 'pending'.
  2. Update deposit status to 'success'.
  3. Increase `users.balance` by `deposit.amount`.
- GET `/history`: Return user's deposit logs and transaction logs.

D. Purchase & Atomic Fulfillment (`/api/buy`)
- POST `/`: [CRITICAL TRANSACTION LOGIC]
  Wrap inside an atomic SQLite Transaction:
  1. Check user exists and get current balance.
  2. Get product price and verify `user.balance >= product.price`. Throw error if insufficient.
  3. Query available stock item: `SELECT id, content FROM items_stock WHERE product_id = ? AND is_sold = 0 LIMIT 1`.
     * Note: If product.type === 'game_topup', stock content can be "AUTO_FULFILLED".
     * If no stock available, throw error "Out of stock".
  4. Deduct balance: `UPDATE users SET balance = balance - ? WHERE id = ?`.
  5. Mark item as sold: `UPDATE items_stock SET is_sold = 1 WHERE id = stock_item.id`.
  6. Insert into `transactions`: Log `user_id`, `product_id`, `price`, `target_data`, `delivered_content` = stock_item.content, status = 'completed'.
  7. Commit transaction and return JSON response: `{ success: true, delivered_content: stock_item.content, new_balance }`.

E. Admin Panel (`/api/admin`) - Middleware restricted to role='admin'
- POST `/products`: Create new product.
- POST `/stock/bulk`: Insert multiple lines of credentials/vouchers into `items_stock`.
- GET `/deposits/pending`: List all pending user deposits.
- POST `/deposits/approve`: Force confirm deposit ID and credit user balance.
